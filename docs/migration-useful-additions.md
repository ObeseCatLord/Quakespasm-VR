# Useful Ironwail and QSS-M additions absent from both bases

These 11 candidates are **optional proposals**, distinct from required inherited/product parity and the user's already requested performance work. “Absent” means the concrete behavior was not found in the bounded source scopes at the [recorded MAIN, XR, DONOR, QSS and IRON pins](migration-feature-map.md#sources-and-coverage); it is not a claim about every version of those engines. No benefit has been measured and no candidate is implemented by this document.

Priority is an engineering recommendation: A has a direct responsiveness or VR-quality use; B is useful when its specific compatibility need exists; C needs a demonstrated workload or product demand. Start with narrow changes at existing subsystem owners. The detailed [network](migration-network-map.md) and [renderer](migration-renderer-map.md) audits carry the implementation/absence evidence for their IDs.

| ID / priority | Existing feature / donor | Why it is useful | Narrow integration and acceptance |
|---|---|---|---|
| CAND-UX-001 / A | Background save writing from a captured snapshot, QSS-M and Ironwail | Potentially shorten autosave stalls in large maps and VR. Snapshot capture/serialization can still cost frame time. | Adapt the existing save owner and vkQuake job/lifetime system; copy all required immutable state before worker access. Preserve fork co-op dialect, client slots, hub data, completion/error/cancel semantics. A save during active multiplayer must restore the captured state and report failure without corrupting the previous save; measure main-thread capture and total save time. |
| CAND-NET-003 / A | Cancellable, frame-driven connection retries, QSS-M | Keep menus and VR responsive while an address is unreachable. QSS DNS lookup remains synchronous. | Extend existing connect state; integrate catalogue reconnect/cancellation, map transitions and shutdown. Unreachable server can be cancelled while frames continue. Resolve DNS separately only if profiling shows it still blocks. |

Restore/reset entities, stats, lights, particles, beams and sound coherently; preserve live head-pose comfort. Forward/back seek lands consistently without contaminating subsequent playback. |
| CAND-PERF-001 / A | Surface-anchored dithering, Ironwail | May reduce camera-relative noise motion in dark gradients, relevant to stereo stability. | Port the formula into the existing world shader and retain palettization settings. | CAND-UX-003 / B | Live visual menu previews, Ironwail and QSS-M | See relevant visual options while adjusting them. | Use existing menu/canvas and render state; keep setting ownership and restoration explicit. | CAND-NET-005 / B | Full CSQC prediction input history and client pmove APIs, QSS-M | Support mods that implement prediction in CSQC. ## Additional implementation evidence for UX candidates

- **CAND-UX-001:** QSS `Quake/host_cmd.c:8450` `Host_BackgroundSave`, thread launch around `8516`; Ironwail `Quake/host_cmd.c:2314` `Host_BackgroundSave`. Snapshot builders and worker serialization are part of the reference. Both workers interact with QC VM context (`PR_SwitchQCVM`); copying a thread entry point is insufficient evidence of thread safety. The adapter must establish immutable data/metadata and VM/thread ownership before using donor workers. Fork and vkQuake `Host_Savegame_f` perform their save writing synchronously in the inspected paths.
- **CAND-UX-002:** QSS `Quake/cl_demo.c:467` `CL_DemoSeekPercent`, `477` `CL_DemoScrub_Begin`, `503` update, `523` end, `541` cancel; rewind snapshots/apply around `152–224`. Ironwail `Quake/gl_screen.c:103,889` provides `scr_demobar`/drawing. vkQuake does have `cls.demospeed` and pause handling; those are not arbitrary seeking or snapshot-backed rewind.
- **CAND-UX-003:** Ironwail `Quake/menu.c:30` `ui_live_preview` and use around `3471`; QSS `Quake/menu.c:335` and preview helpers around `410–503`. Existing fork/donor menus expose settings, but the inspected paths do not implement these live preview helpers.

Absence checks for these three covered MAIN, XR and DONOR `Quake/*.c`, `*.cpp`, `*.h` source declarations and inspected the alternative save/demo/menu paths. The search family was `Host_BackgroundSave|CL_DemoSeekPercent|CL_DemoScrub|ui_live_preview|SaveData_`; zero matches at all three pins. These symbol searches support, rather than replace, the behavior inspection.

## Useful features that are already available

Do not count these as additions missing from both engines:

| Feature | Existing owner / treatment |
|---|---|
| Gyro and flick-stick controls | vkQuake `Quake/in_sdl.c` (`gyro_enable`, `joy_flick`). Preserve as desktop/controller features; do not automatically apply desktop gyro to VR aiming. |
| Console selection, copying and hyperlinks | vkQuake `Quake/console.c` selection/copy/link handling. Keep donor UI and adapt only shared canvas/input seams. |
| Controller alternate-modifier bindings | vkQuake `Quake/keys.c`, `in_sdl.c`. Preserve existing donor binding semantics. |
| Automatic last-save loading | vkQuake `Quake/host_cmd.c` already has `autoload` handling; a differently named QSS cvar is not proof of absence. |
| Network entity prioritization (`sv_netsort`) | Already in fork and vkQuake. Preserve and measure under multiplayer load. |
| Entity field visualization and `nomonsters` | Already in both; preserve diagnostic/QC interfaces. |
| Alias instancing | Fork and Ironwail have it; generic donor alias instancing is a required adaptation, PERF-017, not new optional scope. |
| PNG/TGA/JPG model and level textures, fullbrights, WAD3, lightmapped liquids, lightstyle interpolation | Donor mechanisms are mapped as ASSET-001–009, including lookup differences and interpolation policy/dependency. |
| Threaded rendering/loading, compact marksurfaces, dynamic allocation, higher color/depth precision | Donor mechanisms are mapped as PERF-001–019. Actual jumbo-map timings, memory bounds and VR integration remain qualification work. |
| Mod browsing/catalogue install/reconnect, mouse menus, voice and co-op saves | Existing product behavior must be ported; a superficially similar QSS/Ironwail feature is not a replacement mandate. |

This is a selected useful-feature comparison, not a promise to import the whole QSS-M README. Further competitive-networking features (synthetic lag, ProQuake team/ping metadata, map CRC, join-password extensions and detailed loss reports) remain unselected follow-ups. Features newly advertised online after the audited commit require a fresh pinned implementation audit.
