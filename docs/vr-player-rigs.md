# Code-defined VR body rigs

VRIK poses a skeleton. The rerelease Ranger (`player.md5mesh`) has one, but a
mod that ships its own `progs/player.mdl` replaces the Ranger: the MD5
companion is only used when it comes from the same or a later search path
than the MDL. Before 2.3.5 a tracked player in such a mod was drawn with the
mod's vertex-animated model and no body tracking, and QBJ3 needed a separate
`player_models/qbj3` package.

`Quake/r_player_rig.c` now builds a skinned avatar from the mod's own model
at load time. No file is installed and nothing is networked.

## Table

`Quake/vr_player_rigs.h`, generated by `Misc/vr-player-rigs/generate.py` from
`calibrations.py`, holds one row per mesh, matched with
`VR_WeaponFamilySignature` (counts and frame-0 positions, so reskins and
copies in other mods share a row). A row gives a standing reference frame and
19 joint positions on it, in r_avatar semantic order. Head, Hand and Foot are
the base of the skull, the wrist and the ankle, as on the Ranger.

| Key | Mesh | Used by |
| --- | --- | --- |
| `ad` | Arcane Dimensions player (733 verts) | AD and its forks: mc_hj26, Gibtropolis, hwjam2/4, Mjolnir, q30a1024, Ravenkeep, TCJ, rooftop jam |
| `stock` | classic player | mods that ship their own copy (Rogue, `vr`, ...) |
| `zer` | Zerstorer layout of the classic mesh | Zerstorer, Alkaline, Lim jam |
| `lq1`, `bonk`, `warp`, `peril`, `mcj2` | each mod's player | Quake 1.5, Bonk jam, Warpspasm, Peril, MCJ2 |
| `qbj3`, `qbj3p` | `player_qbj.mdl` and `player.mdl` | QBJ3 |

## Build

- **Skeleton.** The Ranger's joint hierarchy and bind orientations (MD5 axes
  turned to MDL axes). Each bone keeps the model's length from the table and
  takes the Ranger bind direction. The Hip and Spine2 use a two-vector frame
  (up and left-right) so the pelvis and shoulders keep their twist.
- **Weights.** Distance to each bone segment in the reference frame; a
  vertex past the body's midline cannot take the opposite side's limbs; within
  8% of the model height of the adjacent bone it blends with it. A separate
  mesh piece that is mostly forearms and hands (a held weapon, a two-handed
  hammer) follows its majority bone rigidly.
- **Unposing.** Each vertex moves with its bones from the reference frame to
  the Ranger bind pose, so the existing bind-relative Ranger retargeting
  applies unchanged. Zero-area faces and faces that would stretch more than
  2.5 times (a handle spanning both hands) are dropped.
- **Skin.** Skin 0 through the palette, fullbright colours as the glow map.
  Player shirt and pants colours are not applied, as for custom packages.

## Selection

Only a tracked player whose avatar choice is the default Ranger, whose model
has no MD5 companion and whose frame is not a death frame (stock ordinals
41-102) uses the rig. An installed `player_models/qbj3` package still takes
precedence in QBJ3. Explicit avatar choices are unchanged. Models whose frame
names are the stock names in another order (Zerstorer's added chainsaw
frames) are mapped to the stock ordinal by name.

The rig keeps whatever the reference frame holds (the AD axe, MCJ2's pickaxe,
Bonk's hammer); no Ranger prop is attached.

## Limits

- The rig keeps whatever the reference frame holds: AD-family players carry
  the axe, MCJ2 the pickaxe, Bonk the hammer, whatever weapon is in use.
- Untracked poses come from the Ranger animation, whose stands are
  bent-kneed; an upright model (Peril) stands lower than its own frames. A
  tracked player's height comes from the headset.
- Shirt and pants colours are not applied.

## Tools

- `vr_player_rigs` lists the rigs built this game; `vr_player_rigs build
  <model>` builds one without a tracked player; `vr_player_rigs dump` writes
  each as a `player_models`-style package under `vr_player_rigs/` in the
  write root for inspection.
- With `developer 1`, `r_player_rig_untracked 1` shows the rigs on players
  without tracking (chase camera checks on desktop).
- `tests/run_vr_player_rigs.py --base <game tree>` builds and checks every
  rig whose mod is installed (needs a display and the rerelease `pak0.pak`).

To add a mesh: render a standing frame, place the joints, add a `Pick`, run
`generate.py --base <game tree>`, rebuild and run the test.
