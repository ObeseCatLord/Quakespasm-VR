# Complete-scope feature map for the 2.0 migration

This is the working feature checklist for moving the inherited QuakeSpasm OpenVR product and all surviving project work onto vkQuake. It maps **185 behavior/work items**: 124 product, VR, platform and goal items below, 29 [network items](migration-network-map.md), and 32 [renderer/loading/asset items](migration-renderer-map.md). Items overlap where a user behavior crosses subsystem boundaries; this is not a count of independently implemented features. The [combined CSV](migration-feature-map.csv) includes destination owners, source evidence and acceptance criteria.

The [11 optional additions](migration-useful-additions.md) are existing Ironwail/QSS-M features absent from both pinned product branches and vkQuake within the audited scopes. They are recommendations to evaluate, not silent additions to the required release. Features already supplied by vkQuake are explicitly retained rather than ported again.

This records the current scope-inventory checkpoint, **not migration or runtime parity certification**. Source anchors demonstrate relevant implementation; they do not prove behavioral equivalence. The source OpenXR/Vulkan experiments are partly integrated or unqualified, and the current 2.0 backend remains dormant. Hardware and final end-to-end tests are pending. Later discovered behavior gets an ID before its source is discarded.

## Implementation order and architecture

| Phase | Work and dependency | Smallest observable completion gate |
|---|---|---|
| P0 | Preserve sources/history/interfaces; label requirements, donor equivalents, experiments and optional extras. Keep upstream provenance and licenses. | Every imported module has a source pin, feature owner and explicit treatment; historical deletions are reviewed. |
| P1 | Keep donor desktop intact; connect existing VR runtime state machine at renderer-owned Vulkan device/frame boundaries, then pose/input/canvas seams. | Load a stock map in desktop and OpenXR, see correct distinct eyes, move/aim/shoot, open menu, lose/recover focus, disable VR and quit cleanly. Initial diagnostic two-pass rendering is insufficient to exit P1: pass the multiview/lifetime proof below before bulk P2/P3 migration. |
| P2 | After the P1 proof (the minimal coupled network slice needed for P1 is in bounds), donor networking/parser/QC owners plus fork command duration/redundancy/prediction; establish private/public dialect distinction before payload integration. Bring co-op save/restore and physics lifecycle across coherently. | Remote and listen clients move/fire, survive loss/reconnect, restore co-op state and retain native mod physics. Dedicated cadence is independent of render rate. |
| P3 | After the P1 proof, wheel, calibration, physical melee/Gorilla, co-op UI, avatars/FBT, voice/acoustics, catalogue, assets and complete QC surfaces. | Source-vs-2.0 behavior on representative mods, desktop and VR. Audio/QC/render threads retain one owner per state. |
| P4 | Complete and optimize the P1-proven donor multiview/task/visibility adaptations across eligible passes, then opt-in eye/fixed foveation and measured large-map gains. | Both eyes remain correct at visibility boundaries; mj4m1 route captures CPU/GPU tails, draw counts and missed frames. Required UI/weapon detail remains readable. |
| P5 | Consolidated software, native platform and hardware qualification; packaging and upstream merge rehearsal. | Windows/Linux x86-64/Linux ARM64 desktop and OpenXR qualify; Steam Frame streaming and standalone; Beyond 2e/Monado with and without gaze. The inherited OpenVR behaviors are checked through OpenXR, not by retaining a second runtime backend. |

**P1 exit proof, before bulk feature migration:** donor tasks remain enabled; representative opaque geometry uses actual multiview; a lit moving brush renders correctly; two instances of the same MD5/custom-avatar asset retain independent tracked poses/equipment and matching shadow poses when enabled. Gameplay, particles, mutable QC/HUD preparation and entity posing advance once per logical frame. Either-eye visibility survives PVS, frustum, backface and moved-submodel rejection. Clean map/session teardown must separate recording completion, actual queue submission, XR image release and GPU resource retirement. This one gate serves XR-002/010/011, AV-007 and PERF-002/013/015/021; it does not require separate frameworks. Per-eye transparency/UI is allowed where required for correctness. One queue submission containing two full eye renders is not single-pass stereo.

Donor evidence: `Quake/gl_screen.c:1587–1599` joins drawing while the end-render task remains pending; `Quake/gl_vidsdl.c:3518` performs later queue submission. `Shaders/indirect.comp:77–83` uses one view origin for backface rejection, including moved submodels. PVS union alone cannot make this stereo-safe. Preserve the existing queue mutex and runtime synchronization rules; do not force GPU completion every frame merely to release a submitted image.

**Runtime migration qualification:** Windows, Linux x86-64 and Linux ARM64 OpenXR targets must demonstrate Vulkan eye-image submission, pose/controller input, haptics, map change, focus/reconnect and disable/re-enable. Source `Quake/vr.c:9356–9359` submits an OpenGL texture through OpenVR; the behaviors, rather than the old transport API, are the reference. No OpenVR Vulkan backend is required by the user's OpenXR and desktop release targets.

Phases express dependencies, not a ban on independent work or a promise of performance. Source rows can list an earlier phase for their shared owner and a later phase for qualification. No build/runtime tests were run for this documentation pass. The user will perform live headset, multiplayer and eye-tracking testing after implementation; implementation work remains responsible for build/static verification, review, and fixing issues those later tests reveal. Targeted local experiments are allowed when needed to choose a performance change.

Hard design gates:

- **Wire dialect and cadence:** `PEXT2_EXPLICITCMDMSEC` collides with QSS-M `PEXT2_INFOBLOBS` at `0x80`; private svc57 also collides. Retain donor public parsing and explicitly identify the fork dialect at existing negotiation/dispatch boundaries. Do not advertise private payloads under public feature names without a discriminator. Exact legacy same-build acceptance versus broader peer interoperability needs a compatibility decision before implementation; there is no reason to create a second transport or prediction owner.
- **Save formats:** resolve fork multiplayer versions and donor save extensions by reading actual format discriminators and preserving round trips. Specifically, source `host_cmd.c:1175–1177` uses 5/6/7 for legacy/multiclient/current, whereas donor `host_cmd.c:1656–1657` uses 5 for classic and 6 for KEX. A matching version number alone is not sufficient. Keep fork multiplayer identity/pending-slot/hub state and donor supported fields; no silent downgrade to ordinary single-player saves.
- **QuakeC:** reconcile each numeric/name/VM-permission entry and call timing in existing donor registries. Porting the entire fork VM or calling gameplay hooks once per eye would regress mods and duplicate policy.
- **Renderer:** reuse vkQuake task workers, command/staging/resource lifetimes, model loaders and texture/lighting owners. Adapt actual stereo incompatibilities (single view origin, projection, eye layer, culling); do not import a second Vulkan renderer or old GL resource system. Any temporary two-pass path shares the same owners.
- **Visual baseline:** retain vkQuake's default lighting, materials, particles and effects. Port fork-only visual behavior where a mod or VR feature actually needs it, through the existing Vulkan owners; distinguish that from an alternate lighting or graphics stack. VkQuake already has FTE scripted particles and rain/snow entry points (`r_part_fte.c`, `cl_tent.c`, `pr_ext.c`), so those mechanisms need compatibility checks rather than a wholesale copy. The requested lightstyle interpolation correction affects only the CPU lightmap fallback; the default GPU path remains vkQuake's.
- **Visibility/foveation:** conservative union of both-eye PVS/frusta; shared work once, per-eye rejection only where safe. Lower peripheral shading is not permission to remove geometry outside the gaze region. Gaze is optional/off by default; unavailable/stale/invalid gaze restores full quality. Fixed foveation is explicit-only and never a fallback. Multiview and shading-rate/density-map capability combinations require independent qualification.
- **Platforms:** Linux ARM64 is a native desktop/OpenXR client release target, including a compatible native audio SDK build. Steam Frame standalone must not be reduced to a streaming-only promise. Eye tracking is not required to start or play on any headset.
- **Upstream maintenance:** keep donor structure and narrow feature commits, retain source attribution, and periodically merge pinned upstream updates in a separate integration worktree. No wholesale old `gl_*`, model loader, allocator, host loop or networking file replacement just to avoid adapting callsites.

Required verification includes cvar defaults/flags and saved config migration, command and QC compatibility, mod resource lookup precedence, source-vs-donor save parsing, deterministic movement/packet cases, desktop/VR images and actual user interactions. Counters and mocks are supporting evidence, not completion. The named map matrix includes mj4m1, ad_tears, tershib/shib1_drake, peril/tavistock, stock z-fighting doors/lifts, no-VIS and large BSP2; exact mod revision/settings must accompany performance results.
