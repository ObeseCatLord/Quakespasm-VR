# Player models in QBJ3

Select a model in **Multiplayer > Setup > Player model**, then accept the
changes. Installed custom models can also be selected in the console:

```text
player_models
cl_avatar marmotranger
cl_avatar chino
```

The `player_models` command lists packages actually discovered by this client.
Install packages under `player_models/<key>/` in the game-content root and
restart the client after adding or changing one. Every viewer needs matching
custom-avatar package contents. These are cosmetic replacements: they do not
change the server's player physics, weapon inventory or damage.

In QBJ3, an explicit model selection takes precedence over the default native
player enhancement. `cl_avatar ranger` restores the native QBJ3 player; eligible
tracked VR players then use the installed `player_models/qbj3` rig. Without a
valid tracked pose, the default remains the original mod player. Custom selected
avatars also work for untracked players using the existing animation retargeting.
An explicitly selected supported alternate also remains visible through the
known player-slot death frames, without using a live tracking pose. Native
Ranger corpses and unsupported player-model frames are not replaced. QBJ3's
post-respawn body-queue corpse uses its copied Quake player-colormap to select
the current matching scoreboard slot's avatar. A later avatar selection, slot
reuse, or descriptor change can therefore update an existing queued corpse;
the engine deliberately does not freeze or infer historical identity.

For avatars configured to receive attached equipment (`equipment ranger`, also
the manifest default), the supported QBJ3 package supplies its native layout:
shotgun in the dominant hand and wrench on the back. Both remain visible across
weapon changes, as on the supplied QBJ3 rig; these are not separate viewmodels
or indicators of the actual selected weapon. Prop dimensions are independent
of avatar display scale. `equipment native` instead preserves an avatar's own
authored equipment. Chino must use the attachment option to receive these props.

The equipment source is the verified `player_models/qbj3` package, including
its skin and optional fullbright skin. It is **not** generated by the akimbo
weapon splitter. A missing or different equipment package leaves the selected
avatar visible without appended equipment. A missing/mismatched selected avatar
falls back to the original QBJ3 player rather than substituting another custom
model. The server relays identity and tracking; it does not download these files
to viewers.

The official rerelease player MD5 data is still needed as the canonical
animation/pose source. Enable VRIK with `vr_vrik 1` to see tracked poses. Use a
second connected client to inspect another player's model: this replacement
path does not draw a third-person replacement over your own first-person view.

Developer note: the native equipment adapter pins the known QBJ3 package's
content digest in `R_VRIKQBJ3EquipmentModel`. Changing that package's manifest,
mesh or skins requires revalidating the attachment geometry and updating the
pin; otherwise the optional props are deliberately omitted.
