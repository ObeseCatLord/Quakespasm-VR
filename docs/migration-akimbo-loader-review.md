# Akimbo model-loader boundary: Astra senior review

The inherited OpenVR akimbo path has packet fields on `2.0`, but no OpenXR
per-hand producer or split-model drawing yet. This review covers its **asset
boundary only**. The donor is `../quakespasm-openvr/Quake/vr_mdl_split.h` and
`Quake/gl_model.c:1034-1152`; the destination is `Quake/gl_model.c` and the
existing vkQuake alias/texture owners. Akimbo gameplay is not complete when
this loader slice lands.

The local QBJ3 source files match the donor's pinned inputs: nailgun size
1,250,396, CRC32 `497d6bce`; berserk size 656,804, CRC32 `c3af3566`. The
donor splitter produced the expected left/right output sizes and CRCs for both
files. It copies the header and skin prefix before rewriting geometry, so the
single embedded skin keeps its original byte offset. This proves the pure
transformation against these installed assets, not vkQuake loading or drawing.

| Review recommendation | Disposition |
| --- | --- |
| Put generated bytes behind a narrow `Mod_LoadModel` adapter; keep vkQuake's alias loader, texture manager, animation and GPU upload. | **Adopt.** The model loader remains the sole owner. Shipping pre-generated files or transplanting the donor loader would add asset/version or renderer coupling. |
| Expose only the four paired recipes (QBJ3 nailgun/berserk, Enyo SMG, Dwell berserk) through eight exact private names. | **Adopt.** Copy the complete pure splitter for future source features, but do not expose its unrelated dominant-hand recipes through the loader yet. |
| Force exact private pair names to retain classic MDL, including file-backed overrides. | **Adopt.** Target `Mod_LoadModel` otherwise loads complementary MD3/MD5 under `r_enhancedmodels`, and `Mod_Extradata_CheckSkin` can select those over the split MDL. Ordinary models retain vkQuake's enhancement policy. |
| Carry original embedded-skin source separately from private model identity. | **Adopt.** The generated skin pixels have the same source offset, while `TexMgr_ReloadImage` reopens the stored source filename. Pass the original name only to embedded texture reload records; keep private cache names and external lookup. |
| Keep allocator ownership explicit. | **Adopt.** Splitter output uses `malloc`/`free`; `COM_LoadFile` uses `Mem_Alloc`/`Mem_Free`. Do not pass one allocator's buffer to the other's free call. |
| Put loose-pair completeness and per-hand validation in the general loader. | **Reject.** That is presentation/weapon-selection policy. The future akimbo consumer must select a complete pair and validate both models' classic geometry, frames, vertices and scales before suppressing the paired fallback. |
| Cache every generation failure globally. | **Reject.** Missing files and allocation failures should remain retryable. Any cache of deterministic incompatible source bytes must reset at existing model boundaries. |

The smallest integration proof is a QBJ3 nailgun pair loaded by target
`Mod_ForName`: verify 19 frames and 988/980 vertices, Vulkan draw/animation of
both halves, embedded base/fullbright texture reload after generated bytes are
freed, full model reset, and ordinary desktop model enhancement unchanged.
Repeat the selection gate with enhancement enabled, private MD3/MD5
companions, complete and incomplete overrides, and wrong source bytes. The
loader slice should stop and reopen the design if it needs a parallel VFS,
retained generated bytes, duplicated texture or animation state, or changed
skin offsets. Subsequent slices own per-hand rendering, tracked command poses,
server attack semantics, left-handed mapping and native paired fallback.

## Current `2.0` loader checkpoint

The thin adapter now exposes the four paired recipes at the eight exact
private names through vkQuake's normal model loader. The donor splitter is
copied without modification. Exact private names skip complementary MD3/MD5
selection; the default desktop path is unchanged. Generated buffers use
`free`, source VFS buffers use `Mem_Free`, and embedded indexed texture reload
records point to the source MDL. The single lookup table owns names, source
files, game gates and splitter recipe selection.

The Linux Vulkan build passed. In a local QBJ3 desktop session, target
`Mod_ForName` loaded nailgun halves with 19 frames/poses and 988/980 vertices.
Berserk halves loaded with 101 frames/poses and 447 vertices each. Both
berserk base textures recorded `progs/v_berserk.mdl` at source offset 88, and
`TexMgr_ReloadImage` returned for both after generated bytes were freed. A
repeat nailgun load after table consolidation matched the first result, and
an ordinary `id1` startup/map-load/quit exited successfully. These
probes verify the destination loader path but not visible Vulkan animation,
texture appearance, loose-override completeness, or per-hand VR behavior.

A focused Astra implementation review found no blocking code defect in this
adapter. It verified allocator separation, static source-name lifetime through
skin-task joins, all embedded texture reload calls, exact-name enhancement
exclusion, and the four-recipe scope. It retained visible Vulkan animation,
fullbright/recreation, and fallback/override/enhancement branch checks as
qualification work. The asset slice is therefore integrated but **WPN-012 is
still open** until the pair consumer, input producer and gameplay behavior are
implemented and checked.
